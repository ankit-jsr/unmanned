# Newsletter Issue Planner

## When to use

When a newsletter operator has a topic, angle, or content idea and needs a full issue plan
before writing. This skill produces a plan — not prose. Run it before opening a blank doc.

## Inputs

1. **Topic or idea** — 1–3 sentences describing what the issue should cover. Can be rough.
2. **Target audience** (optional) — who reads this newsletter, in one sentence.
3. **Newsletter name or focus** (optional) — helps calibrate tone and CTA.

If the topic is missing, ask for it. If the audience is missing, make a stated assumption
and proceed — do not stall.

## Steps

1. **Sharpen the topic.** Convert the vague input into one specific, arguable insight or
   claim. The sharpened topic should be a sentence someone could agree or disagree with.
   Show your work: state what you started with and what you arrived at.

2. **Generate 3 hook/headline options.** Each should take a different angle:
   - Direct: states the insight plainly.
   - Curiosity: withholds the conclusion to create a question.
   - Contrarian: challenges a common assumption the audience holds.

3. **Propose a 3-section structure.** For each section: a name, a one-line description of
   what it covers, and a target word count. Total target: 400–900 words for most newsletters.

4. **Write one CTA** matched to the newsletter's stage:
   - Early (under 500 subscribers): ask for a share or a reply.
   - Established (500+): can ask for a purchase, a hire, or a referral.
   - If stage is unknown, default to "reply with your take" — always works.

5. **Write 3 subject line variants** in the styles:
   - Direct (states what's inside)
   - Curiosity gap (incomplete sentence or question)
   - Contrarian (challenges a belief)

## Output

A structured one-page plan with these sections in order:
- Sharpened topic (one sentence, with your starting point for reference)
- Hook/headline options (3, labelled)
- Issue structure (table: Section | Description | Words)
- CTA (one sentence)
- Subject lines (3, labelled)

## Don't

- Do not write actual issue content — that is the writer's job. Plans only.
- Do not produce more than one full plan per call. If the user has multiple ideas, ask them
  to pick one.
- Do not invent subscriber counts or audience data the user did not provide.
- If the topic is so broad it could be ten different issues, name the problem and offer
  3 narrowed versions before proceeding.
